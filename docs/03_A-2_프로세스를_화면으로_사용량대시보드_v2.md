### 0-b. 주요 내부 로직 (각 1줄)

- **인증 도메인 화이트리스트**: `ALLOWED_EMAIL_DOMAINS` (쉼표 구분) 미일치 → `/login?error=domain`. 빈 값이면 모든 도메인 허용.
- **어드민 판정**: `ADMIN_EMAIL` 환경변수 (쉼표 구분). 어드민만 `/member` + `/team/[userId]/dashboard` + 팀 페이지 Last Sync/Top Sessions 카드 노출.
- **API 키 발급**: CLI 가 OAuth 후 `/api/cli-auth?port=9988` 호출 → 32바이트 hex 신규 발급 + sha256 해시 DB 저장 → `127.0.0.1:9988/?apiKey=...` 리다이렉트로 CLI 에 전달.
- **데이터 수집 스케줄**: macOS launchd `StartInterval` 7200초 (2시간), sleep 시 카운트다운 정지 → wake 즉시 1회 fire. Windows Task Scheduler 0/6/12/18 + `StartWhenAvailable=true`.
- **수집 페이로드**: codeburn report x5 (today/week/month/30days/all) + ccusage daily, `Promise.allSettled` 600초 timeout → POST `/api/ingest` (X-API-Key).
- **ccusage 머지**: `body.ccusageDaily` 비었거나 missing 인데 prev 에 데이터 있으면 prev 의 ccusageDaily 보존 (1회 timeout 으로 토큰 wipe 차단).
- **Boundary 감지**: `today.period` 라벨 (`Today (YYYY-MM-DD)`) 정규식으로 사용자 로컬 today 추출 → 월요일/1일 boundary 계산. timezone NULL 이어도 동작.
- **Snapshot 승격**: `currentDayStart/WeekStart/MonthStart` 가 prev 와 다르면 prev rawJson 을 `period_snapshots` 에 INSERT (daily/weekly/monthly).
- **Retention**: weekly 5주, monthly 12달, daily 7일 보다 오래된 period_snapshots 삭제.
- **Period 필터**: `today / month / 8days / 30days / all` 5개. legacy `week` localStorage 값은 `8days` 로 자동 마이그레이션.
- **Heatmap 길이 적응형**: `clamp(ceil(데이터일수/7), min=15, max=26)` 주. UI 라벨도 동적 (예: "활동 히트맵 (16주, 비용 기준)").
- **효율 등급**: 6개 메트릭 (cache/one-shot/cost-per-session/calls-per-session/cost-per-call/output-input ratio) 각각 5단계 (탁월/양호/보통/부족/경고) → 종합 등급은 cache×0.4 + 1shot×0.4 + cost×0.2 가중치.
- **stale 멤버 필터** (팀 페이지): 멤버 `rawJson.{month,today}.daily[0].date` 가 현재 UTC YYYY-MM(-DD) 와 다르면 0 처리 + 활동 합산에서 제외.
- **DashboardView 자동 분기**: `!user.lastSyncedAt && !viewOnly` 면 `/setup` 으로 redirect. `!overview` 면 sync 명령 화면 표시.
- **CLI ownership preflight**: install.sh 가 `~/.npm` + `~/.primus-usage-tracker` + `~/.primus-usage-key` + LaunchAgent plist 4 위치 모두 root 소유 검사 → 한 번에 chown 명령 출력. `.pkg` Node 감지 시 nvm 전환 권유.

## §1. A-1 요약 블록

**A-0 핵심 가설**
Primus Labs 개발자 10명이 Claude Code 세션마다 자동 수집된 사용량 데이터를 개인 대시보드 + 팀 랭킹으로 확인하면서 (1) 자기 워크플로우를 최적화하고 (2) 가벼운 경쟁을 즐길 것이다. **lower bar: 본인이 한 달에 한 번 보면 성공.**

**MVP 경계 3개**
- 제품: Claude Code 사용량 자동 수집 + 사내 웹 대시보드 (Codex/Gemini 제외)
- 타겟: Primus Labs 사내 개발자 10명 안팎
- 목표 행동: 주 1회 대시보드 방문 + 월 1회 자기 통계 보고 워크플로우 변경

**Phase 구조 (코드 검증)**
- P0. 온보딩 & 셋업 (/login → /setup → /dashboard)
- P1. 자동 수집 (UI 없음, launchd/Task Scheduler)
- P2. 조회 — 개인 + 팀 (/dashboard ↔ /dashboard/detail ↔ /team ↔ /team/[userId] ↔ /setup-status)
- P3. (어드민) 팀원 진단 (/member ↔ /team/[userId]/dashboard)

**기술 스택 (코드 검증)**
- 프레임워크: Next.js 14 App Router (web + API 단일 코드베이스)
- DB: Postgres 본번/Supabase, Drizzle ORM
- 인증: NextAuth.js (GitHub + Google), 도메인 화이트리스트 + ADMIN_EMAIL
- UI: Tailwind + Recharts (AreaChart) + react-activity-calendar (heatmap)
- CLI: Bun + commander, npm 글로벌 ccusage + codeburn 의존
- 데이터 수집: launchd (`StartInterval 7200s`) / Windows Task Scheduler. SessionEnd hook 미사용 (코드에서 removeHook 으로 제거).
- 비밀 저장: keytar (Mac Keychain / Win Cred / Linux libsecret) + `~/.primus-usage-key` 파일 fallback
- 차트: 자체 막대 (CSS bar) + Recharts AreaChart (팀 By Member/Total) + ActivityCalendar (heatmap)

#### 4-b. UX 의도

- **2개 OAuth 동등 노출**: 회사 GitHub 계정과 회사 Google 계정 모두 정식 사인. 한쪽이 안 되는 멤버 존재 시 fallback. (v1 의 "GitHub만" 가설은 코드에서 Google 도 받기로 진화)
- **회사 도메인 화이트리스트는 OAuth 콜백 후 검증**: 사용자가 OAuth 끝낸 다음에야 거부 메시지 — 도메인 노출은 환경변수에만 있고 사용자에게 미리 안 보임. 회사 멤버 전용 메시지 ("팀 멤버 전용") 로만 사전 안내.
- **에러 메시지 inline**: 별도 페이지로 안 가고 같은 화면에 빨간 배지. 사용자가 다시 시도하기 쉬움.

#### 4-c. 인터랙션

- `[GitHub로 시작하기]` 클릭 → `signIn("github", { callbackUrl: "/dashboard" })` → GitHub OAuth → 콜백 → `signIn` 콜백에서 도메인 검증 + DB 에 user 없으면 INSERT → 통과 시 `/dashboard` 로
- `[Google로 시작하기]` 클릭 → 동일 흐름
- 도메인 거부 시 → `/login?error=domain` 으로 리다이렉트 → 빨간 배지 노출
- 일반 에러 시 → `/login?error=...` → "로그인 중 오류가 발생했습니다."

#### 4-d. 상태

- 정상: 로고 + 2개 버튼 + (에러 없음)
- `?error=domain`: 빨간 배지 "허용되지 않은 이메일 도메인입니다."
- `?error=*` (기타): 빨간 배지 "로그인 중 오류가 발생했습니다."
- 인증 진행 중: 외부 OAuth 페이지로 이동하므로 본 화면 자체는 변화 없음
- 빈 상태: 없음

#### 4-b. UX 의도

- **OS 자동 감지로 install 명령 분기** (`navigator.userAgent` 검사): macOS/Linux 는 `curl ... | bash`, Windows 는 `irm ... | iex`. 사용자가 OS 선택 안 해도 됨 — 첫 인상 마찰 0.
- **"한방 설치" 강조 + 수동 npx 는 details 토글 안에**: 대부분 사용자에게 install.sh 가 정답. .pkg Node 권한 사고 같은 것을 install.sh 가 자동 진단/안내하므로 직접 npx 보다 안전.

- **2단계 폴링 체크리스트**: `hook 등록` + `첫 데이터 수신`. 사용자가 install 명령을 어디에 붙여넣고 OAuth 진행 중에도 이 페이지가 살아 있어 진행 상황 확인 가능. 2초 간격 polling — 즉각성.
- **Step 1 의 backfill 종료 조건 분리**: backfill (90일치) 은 종료 조건 아님. hook + 첫 세션만 끝나면 다음 단계 가능. (v1 SO1 결정 그대로 유지)

#### 4-c. 인터랙션

- 진입 시 `Intl.DateTimeFormat().resolvedOptions().timeZone` 자동 감지 → select default 값
- `userAgent` 검사 → `mac` / `win` / `other` 중 하나로 OS 상태 결정 → install 명령 + 배지 라벨 분기
- 타임존 select 변경 → `setTzSaved(false)` → `PATCH /api/user/timezone` body `{timezone}` → 성공 시 `✓ 저장됨` 표시

- "이미 Node.js 가 있다면" `▾` 토글 → npx 명령 노출 + 동일 [복사] 버튼

- 데이터 fetch: `apiUrl(period, weekOffset, monthOffset, dayOffset)` 으로 GET `/api/dashboard?period=...&weekOffset=...&...&userId=...` (viewOnly 일 때 `userId`)

- `!data.user.lastSyncedAt && !viewOnly`: 즉시 `/setup` redirect
- `!data.overview && !viewOnly`: sync 명령 화면 (full-page) + 4초마다 polling 으로 overview 가 채워지면 자동 화면 전환

- Period 탭 클릭 → `setPeriod(p)` + `setWeekOffset(0); setMonthOffset(0); setDayOffset(0)` (모든 offset 라이브로)
- offset select 변경 → 해당 setter 호출 → useEffect 가 재 fetch
- 멤버 셀렉터 (viewOnly 모드만, teamMembers 가 있을 때) 변경 → `onMemberSelect(userId)` 호출 (없으면 `router.push(/team/${userId}/dashboard)`)

  - `[설명]` 클릭 → 해당 modal open (`CacheHitModal` 등)
  - `[액션]` (badGrade 일 때만) 클릭 → 같은 modal 의 `methodsOnly` 모드 open

- Modal: Esc / 외곽 클릭 / [×] 모두 close
- Heatmap: ActivityCalendar 자체 hover tooltip (count 표시)
- 카드 길이가 임계값 (15 또는 45) 초과 시 자동 scroll 박스로 전환 + 우상단 scroll 배지

#### 4-d. 상태

- 정상 (위)
- Loading: 우측 fade-in `loading...` (status loading 또는 data null)
- Fetch 실패: error 화면 + 재시도 버튼

- 오프라인 (fetch 실패): error 상태와 동일

## §6. Kill / Go / Hold 판정

**Go**

근거 3줄:
- v1 산출 후 1주일 운영 → 핵심 기능 (개인 dashboard + 팀 페이지 + ingest) 안정적 동작. 8명 정기 sync 중. **lower bar 검증됐음** ("본인이 한 달에 한 번 보면 성공" → 실제로 어드민이 매주 1회 이상 보고 있음).

- v2 [SO 결정 필요] 3개 모두 옵션이 명확 + Claude 추천 + 이유 박힘. 빌드 도구 AI 가 다음 라운드에서 반영하면 끝.

## 적대적 압박 — Kill 할 이유 3개

A-2 v2 단계의 Kill 이유는 **운영 1주일 후 노출된 UX 의 구조적 결함**.

1. **/dashboard/detail 라우트가 존재 가치 없음**:
   - "더보기 → " 진입 동선 미구현 → 직접 URL 만 도달 → 거의 안 쓰임
   - 본문은 By Project 풀 리스트 (메인의 같은 카드와 사실상 중복) + codeburn CLI 안내 (한 번만 보면 됨)
   - **5개 제안 + Done/피드백** v1 의도가 폐기되면서 이 화면의 raison d'être 도 같이 사라짐. Kill 후보 1순위.

2. **/team 의 어드민 vs 일반 사용자 정보 격차**:
   - 일반 사용자 화면: Activity/Cost/Efficiency/TeamActivities/Tools/ShellCommands/By Model 7개 카드
   - 어드민 화면: 위 7개 + Last Sync + Top Sessions = 9개 카드
   - "어드민만 보는 카드 2개" 가 Row 6 으로 뒤에 박혀 있어 일반 사용자가 어드민에게 "그 자료 보여달라" 요청하는 케이스 발생할 가능성. 어드민/일반 정보 라인을 더 명확히 분리하거나, 일반에게도 Last Sync 정도는 노출해야 (자가 진단용).

3. **stale 멤버 0 처리 + SyncBadge 의 모순적 시각**:
   - 서버에서 stale 멤버를 totalCost=0 으로 처리 (period=today/month 시) + 활동 합산 제외
   - UI 에선 SyncBadge 로 "5일 전 sync" 표시 + Efficiency 표에 0 값으로 등장 → "이 사람 0 인데 왜 표시?" 인지 부담
   - 옵션 1: stale 멤버 행 자체 숨김 (어드민에게는 Last Sync 카드로만 노출)
   - 옵션 2: stale 멤버 행은 유지하되 "—" 로 표시 + 명확한 텍스트
   - 현재는 옵션 0 (어떤 처리도 안 함) 상태 — 1주일 운영에서 발견된 미세 UX 결함. v3 갱신 시 정리.

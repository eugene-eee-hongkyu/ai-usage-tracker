### 0-b. 주요 내부 로직 (각 1줄)

- **인증 도메인 화이트리스트**: `ALLOWED_EMAIL_DOMAINS` 미일치 → `/login?error=domain`. 빈 값이면 모든 도메인 허용.
- **어드민 판정**: `ADMIN_EMAIL` 환경변수. 어드민만 `/member` + `/team/[userId]/dashboard` + 팀 페이지 Engagement/Top Sessions 카드 노출.
- **API 키 발급**: `/api/cli-auth?port=9988` → 32바이트 hex 발급 + sha256 해시 DB 저장 → `127.0.0.1:9988` 리다이렉트.
- **데이터 수집 스케줄**: macOS launchd `StartInterval` 7200초 (sleep 시 카운트다운 정지, wake 즉시 fire). Windows Task Scheduler 0/6/12/18 + `StartWhenAvailable=true`.
- **수집 페이로드**: codeburn report x5 + ccusage daily, `Promise.allSettled` 600초 → POST `/api/ingest`.
- **ccusage 머지**: incoming 비었고 prev 있으면 prev 보존 (1회 timeout 으로 토큰 wipe 차단).
- **Boundary 감지**: `today.period` 라벨 정규식. timezone NULL 도 동작.
- **Snapshot 승격 + Retention**: weekly 5주 / monthly 12달 / daily 7일.
- **Period 필터**: today / month / 8days / 30days / all. legacy `week` → `8days` 자동.
- **Heatmap 길이 적응형**: clamp(ceil(데이터일수/7), 15~26).
- **효율 등급**: 6 메트릭 × 5단계 → 종합 = cache×0.4 + 1shot×0.4 + cost×0.2.
- **stale 멤버 필터** (팀 페이지): rawJson today/month daily[0].date ≠ 현재 UTC → 0 처리.
- **DashboardView 자동 분기**: !lastSyncedAt && !viewOnly → `/setup`. !overview → sync 명령 화면.
- **Setup-status fetch 실패**: HTTP not-ok 또는 reject → 에러 화면 + [다시 시도] 버튼.
- **Visit 카운트**: DashboardView mount-time `POST /api/visit` → daily_visits.count + 1 (atomic upsert). today = users.timezone 기준. session.user 만 카운트 (어드민 viewOnly 무관).
- **Dwell 추적 (★ v5 신규)**: DashboardView 가 visibility-change / pagehide / unmount 시 누적 visible 시간을 `navigator.sendBeacon('/api/visit-end', {sec})` 로 전송 → daily_visits.total_dwell_seconds 가산. 백그라운드 탭은 visibility=hidden 으로 자연 정지. 서버 측 4시간 cap (timer 망가짐 보호).
- **Engagement heatmap (★ v5 신규)**: dashboard API 응답 `visitDaily` 가 `{date, visitCount, dwellSec}` 배열. 클라이언트가 dwellSec 으로 색 (5단계: 0 / <2min / 2-5 / 5-15 / 15+) + 분 단위로 변환해 ActivityCalendar 의 count 에 입력. 카드 라벨에 "이번달 N회 방문 · 평균 M:SS" inline.
- **Team Engagement 컬럼 (★ v5 신규, 어드민 only)**: /api/team 이 멤버별 monthVisits + avgDwellSec 응답. 팀 페이지 (구) Last Sync 카드 → "Engagement" 카드로 확장 — 마지막 수신 + 방문/달 + 평균체류 컬럼. 0회 red / 1-3회 yellow / 4+ 정상.
- **CLI ownership preflight**: install.sh 가 4 위치 root 검사 + .pkg Node 시 nvm 권유.

### P1. 자동 수집 (visit/dwell 추가)

```
   [기존: codeburn + ccusage → /api/ingest]

   [v4 visit count]
   DashboardView mount → POST /api/visit (no body)
     → daily_visits.count + 1 (atomic, ON CONFLICT)

   [v5 신규 dwell tracking]
   ┌────────────────────────────────────────────────┐
   │ DashboardView mount                             │
   │   visibleSince = Date.now()                     │
   │   accumulated = 0                               │
   │                                                  │
   │ visibilitychange:                                │
   │   visible: visibleSince = Date.now()             │
   │   hidden:  accumulated += now - visibleSince    │
   │            flush() → sendBeacon                  │
   │                                                  │
   │ pagehide / unmount:                              │
   │   accumulated += (visibleSince ? now - vs : 0)  │
   │   flush() → sendBeacon                           │
   │                                                  │
   │ flush():                                         │
   │   sec = floor(accumulated / 1000)                │
   │   if sec > 0:                                    │
   │     sendBeacon('/api/visit-end', { sec })        │
   └────────────────────────────────────────────────┘
                                │
                                ▼
                  POST /api/visit-end                 │
                  ·session.user → today (user TZ)    │
                  ·sec cap: > 14400 → 14400 (4h)     │
                  ·sec ≤ 0 → 무시                    │
                  ·daily_visits.total_dwell_seconds  │
                    += sec (ON CONFLICT DO UPDATE)   │
```

#### 4-b. UX 의도

- **체류 시간 색 인코딩**: visit count (v4) 보다 정직한 engagement 신호 — "들렀다 5초 만에 닫음" 과 "5분 들여다봄" 을 구분. lower bar 가설을 단순 방문 횟수가 아닌 "정말 봤나" 까지 검증.
- **분 단위 라벨**: ActivityCalendar 의 `count` 필드에 분(`Math.round(sec/60)`) 입력 → hover tooltip 이 "12 on 2026-05-08" → 카드 제목의 "일별 총 분" 컨텍스트로 자연 해석.
- **카드 제목에 이번달 통계 inline**: "체류 히트맵 (15주, 일별 총 분 · 이번달 12회 방문 · 평균 3:40)". 사용자가 본인 engagement 패턴을 한 줄로 잡음.
- **5단계 임계값**: 0 / <2min (글랜스) / 2-5 (가벼운 확인) / 5-15 (집중 검토) / 15+ (깊은 분석). 1~2개월 운영 후 데이터 보고 튜닝.
- **amber 톤 유지**: v4 visit heatmap 과 시각 연속 — 사용자에게 "Row 6 우측 amber = engagement" 일관 멘탈 모델.
- **viewer 본인만 카운트**: 어드민이 다른 멤버 dashboard 봐도 멤버 row 안 늘어남. 어드민의 viewOnly 행위가 멤버 engagement 통계를 부풀리지 않음 — 진단 정확도 보호.
- **백그라운드 탭 자연 정지**: visibility-API 가 표준 처리. 사용자가 다른 탭 보면 dwell 카운트 정지, 돌아오면 재개. 시간 부풀림 없음.

#### 4-b. UX 의도

- **"Last Sync" → "Engagement" 라벨 변경**: 카드 책임이 "마지막 sync 시점" 만이 아니라 "멤버가 도구를 실제로 사용 중인가" 종합 진단으로 확장. CLI sync (자동) ≠ 사용자 실 사용.
- **방문/달 컬럼**: 이번달 (UTC) 방문 합계. 0회 = red (셋업했지만 한 번도 안 봄), 1-3회 = yellow (간헐), 4+ = 정상색.
- **평균체류 컬럼**: 분:초 형식 (3:40). 1초 단위까지 정확. 방문 없으면 "—".
- **어드민 진단 시나리오**:
  - "셋업했지만 한 번도 안 봄" (방문 0회 red) → 멤버에게 도구 가치 직접 안내
  - "들어와서 글랜스만 함" (방문 ≥3회, 평균 <30s) → 도구 UI 가치 부족 신호
  - "들어와서 깊이 봄" (방문 ≥5회, 평균 5min+) → engagement 정상, 데이터 신뢰
- **stale 멤버 효율 표 0 처리 + 본 카드 의 visit/dwell 0** = 명확한 "버려진" 시그널. 두 신호가 같은 멤버에게 동시 발견되면 어드민 액션 트리거.
- **컬럼 width 미세 정의 안 함**: tabular-nums + text-right 만. 멤버 이름 길이 + 시간 형식이 자연 정렬.

## 적대적 압박 — Kill 할 이유 3개

1. **dwell 측정의 정확도 한계**:
   - visibility-API 가 "탭이 visible" 상태만 봄. 사용자가 "탭 visible 인데 모니터 안 봄" (거실 다녀옴, 다른 모니터 봄) 케이스 미감지
   - 결과적으로 "5분 visible 인데 실제 시청 30초" 가 5분으로 카운트
   - 이상적 솔루션은 IntersectionObserver + 마우스/키보드 활동 감지인데 over-engineering
   - 현재로 충분 — 첫 인상 dwell 신호로는 OK

2. **engagement 컬럼이 어드민에게 "감시" 인상 줄 수 있음**:
   - 사내 10명 + 도구 정신 (사용량 가시화) 와 일관되긴 하지만 dwell 까지 보이는 건 "퇴근 시간 측정" 과 비슷한 분위기
   - README / Slack 공지 1줄 ("어드민이 engagement 도 봅니다") 로 처리하기로 했으나 미실행
   - 운영 1주일 후 멤버들 반응 봐서 v5.1 에서 옵트아웃 / 본인만 보기 옵션 추가 검토

3. **5단계 임계값이 임의값**:
   - 0/<2/2-5/5-15/15+ 분 — 어디서 나온 숫자? 지금은 추측 기반
   - 사용자 행동 패턴 (1주~1개월 데이터) 에 맞게 percentile 기반 (P20/P40/P60/P80) 으로 동적 조정 가능
   - 백로그 — 데이터 충분히 쌓이면 v5.1 에서 튜닝

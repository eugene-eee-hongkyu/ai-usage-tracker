# 01 A-0 생각을 문서로 v5

> 00 기획 하네스 정책 v11을 토대로 한다. 작성 전 정책 문서의 "안 읽힘 6원인"·"문장 원칙"·"AI의 역할"·"턴 카운팅"을 참조한다.

---

## 이 문서 사용법

A-0 "생각을 문서로"는 **하네스의 첫 번째 문서**이다. 러프한 서비스 아이디어가 머리에 있을 때, 그것을 A4 1장으로 꺼내서 **"지금 Kill할까 / Go할까 / Hold할까"**를 빠르게 결정하는 도구다.

이 문서에는 두 가지가 같이 들어 있다:
1. **산출물 템플릿** — A-0 산출물이 최종적으로 어떤 형태여야 하는가
2. **워크플로우** — Claude와 플래너가 어떤 순서로 채워가는가

Claude는 이 문서와 기획 하네스 정책 v11을 함께 읽은 뒤 A-0 작성을 시작한다.

---

## 산출물 형태 (A4 1장 목표)

> **분량 구분**
> - **이 문서 (템플릿+워크플로우)**: 분량 제한 없음. 작성 가이드다.
> - **A-0 산출물**: A4 1장 목표. 플래너가 실제로 만드는 문서.
>
> A-0은 "빠른 킬 판정"이 목적이라 산출물이 길면 철학과 충돌한다. 1장 넘기면 압축 대상이다.

### 산출물 구조

A-0의 최종 산출물은 아래 6개 섹션으로 구성된다. 각 섹션의 목표 분량은 "A4 1장 안에 다 들어갈 것"이다.

```
[맨 앞] 1차 독자 선언문 (정책 규격)

1. 핵심 가설 한 문장
2. 왜 지금인가 (2~3줄)
3. 누가 쓰는가 (2~3줄)
4. 러프 유즈케이스 메인 라인 (3~5줄)
5. MVP 경계 (표)
6. Kill / Go / Hold 판정

[맨 끝] Claude의 적대적 압박 — "Kill할 이유 세 가지"
```

---

### 섹션별 상세

**1. 핵심 가설 한 문장**

이 서비스가 실제로 작동한다는 걸 판별하는 전제 한 문장. 이 가설이 틀리면 서비스는 작동하지 않는다.

- 형식: "[구체 사용자 집단]이 [구체 상황]에서 [구체 행동]을 할 것이다."
- 좋은 예: "이직을 고민하는 30대 직장인이, 퇴근 후 혼자 있을 때, 친구에게 말 못하는 고민을 AI에게 털어놓고 해석받을 것이다."
- 나쁜 예: "사용자들이 우리 서비스를 좋아할 것이다." (누구인지·언제인지·뭘 하는지 없음)

**2. 왜 지금인가 (2~3줄)**

왜 이 아이디어가 지금 필요한가. 세상의 어떤 변화가 이 서비스를 가능·필요하게 만들었는가.

- 예: "AI 상담 품질이 작년보다 급격히 좋아졌다. 사주 앱은 많지만 대화형은 아직 없다. 2030년 이전이면 선점 가능."

**3. 누가 쓰는가 (2~3줄)**

타겟 사용자. 나이·상황·현재 대안까지 구체적으로.

- 예: "28~34세 여성, 수도권 거주, 사회생활 5~10년차. 인생 전환기 결정 앞에 있음. 지금은 친구·유튜브·역술인에게 묻거나 무료 앱으로 원국만 본다."

**4. 러프 유즈케이스 메인 라인 (3~5줄)**

사용자가 이 서비스로 뭘 하는지 **메인 시나리오만**. Phase·Step 같은 체계는 여기 넣지 않는다. 그건 A-1로 간다. 여기선 "이런 일이 일어난다"만.

- 예: "사용자가 인스타 광고에서 서비스 발견 → 생년월일시와 고민 한 줄 입력 → AI가 사주 해석을 대화로 풀어줌 → 사용자가 궁금한 것 몇 번 추가 질문 → 정리된 답변 받고 종료."

**5. MVP 경계 (표)**

A-0 단계에서 반드시 고정해야 할 3개. 하나라도 미정이면 Go 불가.

v1에서 5개(제품·채널·타겟·목표 행동·실행안 유형)였으나 v2에서 3개로 축소. 이유: A-0은 "왜+무엇"을 판정하는 단계인데, 제품·사용자가 확정되기 전에 채널이나 실행안 유형을 정하는 건 이르다. 채널·실행안 유형은 A-1 또는 A-2로 미룬다.

| 항목 | 이번 버전에서 고정 | 배제한 것 | 예시 |
| --- | --- | --- | --- |
| 제품 1개 | [무엇 하나를 만들 것인가] | [함께 있으면 좋지만 이번엔 뺀 것] | "AI 대화형 사주 해석 서비스" (타로·MBTI는 제외) |
| 타겟 세그먼트 1개 | [누구 하나에게 먼저 보낼 것인가] | [제외한 세그먼트] | "28~34세 여성, 수도권, 인생 전환기 결정 앞" (남성·10대·지방 제외) |
| 목표 행동 1개 | [사용자가 무엇을 해내야 성공인가] | [제외한 행동] | "첫 대화 세션 완료" (회원가입·웨이팅리스트·단순 방문 제외) |

**왜 이렇게 좁히는가** (1~2줄)
— 이 좁힘이 핵심 가설을 어떻게 검증 가능하게 만드는가.

**6. Kill / Go / Hold 판정**

정책 규격대로 세 가지 중 하나. 근거 3줄.

- **Go** — A-1로 진입. 근거 3줄.
- **Kill** — 여기서 종료. 근거 3줄. Kill은 성공이다.
- **Hold** — 외부 정보 확보 후 재판정. 무엇을 알아야 하는지 명시. 최대 2회.

---

### 산출물 마지막 (Claude의 적대적 압박)

문서가 완성되면 Claude가 **자동으로** 맨 아래에 "지금 이 아이디어를 죽일 이유 세 가지"를 붙인다. 이건 산출물의 일부이고, 플래너의 판정 전에 반드시 보여진다.

---

## 워크플로우 (채우는 순서)

A-0은 **메인 라인 먼저, 체계는 그 위에** 원칙에 따라 아래 순서로 진행한다. 순서가 바뀌면 리뷰 불능 상태가 된다.

### STEP 0: 시작 선언 및 러프 덤프

**플래너의 행동:**
- `A-0 시작` 선언 (Claude의 턴 카운터 개시)
- 머리에 있는 러프 유즈케이스를 자유롭게 쏟아낸다. 정리 안 해도 된다. **분량 제한 없음** — 짧은 몇 줄이든, ChatGPT·다른 Claude 대화 통째로 복붙이든, 수백 줄 문서 붙여넣기든 다 가능. Claude가 이 덩어리에서 메인 라인을 뽑아내는 게 다음 STEP이다.

**Claude의 행동:**
- 턴 카운팅 시작
- 플래너 덤프를 받아 읽되 **아직 문서 작성 시작하지 않음**
- 다음 STEP으로 진행

### STEP 1: 메인 라인 확인 (가장 중요)

**Claude의 행동:**
- 플래너 덤프에서 메인 시나리오만 뽑아 **3~5줄로 요약**
- 플래너에게 "이 메인 라인이 맞나?" 확인 요청
- 이 단계에서는 섹션 1~6 전체 쓰지 않음

**예시 응답 형식:**
```
[A-0 진행: 턴 1/5]

러프 덤프에서 뽑은 메인 라인입니다. 이게 맞는지 먼저 확인해주세요.

---

사용자: 이직·연애·자기이해 고민 중인 30대 직장인
발견: 인스타 릴스에서 "30대 사주 해석" 영상 보고 관심
행동: 생년월일시와 고민 한 줄 입력 → AI와 대화로 해석받음
이탈: 만족스러운 답변 받거나, 의구심 생겨서 떠남

---

이 메인 라인이 Eugene이 생각한 거랑 맞나요? 틀린 곳·빠진 곳 있나요?
```

**플래너의 행동:**
- 확인 / 수정 지시

### STEP 2: 핵심 가설 + MVP 경계 + 나머지 섹션 일괄 제시 (번들링)

정책 v11 역할 5 "번들링" 원칙 적용. v2까지는 STEP 2(핵심 가설 확인)와 STEP 3(나머지 섹션)을 따로 돌렸으나 v3에서 하나로 합친다. 플래너 뇌 부담을 줄이기 위해 한 응답에 결정 필요 항목을 묶는다.

**Claude의 행동:**
- 확정된 메인 라인에서 다음을 한 응답에 다 제시:
  - 핵심 가설 한 문장 (메인 라인에서 자연 도출, 단일 초안)
  - MVP 경계 3개 각각 **옵션 2~4개 + 추천 + 이유**
  - 왜 지금인가 초안 (복수 앵글 제시)
  - 누가 쓰는가 초안

**"초안 떠넘기기 금지" (정책 v11 원칙 5 강화)**

다음 패턴은 금지:
- ❌ "Eugene이 생각하신 거 있으시면 한 줄 주시고, 없으시면 초안 달라고 말씀해주세요"
- ❌ "A / B / C 중 어느 것으로 갈지 결정해주세요" (추천·이유 없음)

다음 패턴은 필수:
- ✅ "왜 지금인가 초안 3개 — (앵글 A) / (앵글 B) / (앵글 C). Claude 추천: A+B 병행, 이유: ..."
- ✅ "목표 행동 옵션 — A. 대화 완주 / B. 최소 1회 질문 후 완주 / C. 3회 질문 다 쓰고 완주. Claude 추천: B, 이유: 핵심 가설과 직결"

플래너의 입력이 비어 있을 때 Claude가 먼저 복수 초안을 쓴다. 플래너는 고르거나 수정하거나 자기 것으로 대체한다.

**플래너의 행동:**
- 메인 라인·핵심 가설 수정 / MVP 3개 선택·수정 / 왜 지금인가 앵글 선택을 **한 번에** 답변
- 번들 중 일부만 답해도 됨. 미답 항목은 Claude 추천대로 갔다고 간주

### STEP 3: 전체 조립 + Kill할 이유 3개 자동 생성

**Claude의 행동 (필수):**
- STEP 2의 플래너 피드백을 반영해 A-0 산출물 전체 클린 조립
- 산출물 맨 아래에 **"Kill할 이유 세 가지"** 자동 추가
- 이는 정책 역할 1(적대적 압박)의 의무
- Kill 이유는 구체적이고 강하게. 완충어 금지

### STEP 4: Claude 판정 제안 + 플래너 확정

**Claude의 행동:**
- STEP 3의 Kill 이유 3개를 포함해 전체 맥락을 본다
- Go / Kill / Hold 중 하나를 **추천** + 근거 3줄 작성
- 플래너에게 "이 판정으로 가시겠습니까, 아니면 다른 판정?" 확인

**플래너의 행동:**
- Claude 추천대로 확정하거나, 다른 판정으로 수정
- 수정 시 Claude가 근거 3줄을 해당 판정에 맞게 재작성

**v1과의 차이:**
v1은 "플래너 판정" 단계였다. v2부터는 Claude가 먼저 추천하고 플래너가 승인·반박. 플래너 뇌 사용을 줄인다는 정책 철학과 일치. "적대적 압박"을 Claude가 담당하는 것과 같은 원리.

## 턴 관리 (정책 v11 카운팅 메커니즘)

A-0의 턴 상한은 **5턴**이다. 70% 경고는 **4턴째**.

Claude는 매 응답 맨 위에 `[A-0 진행: 턴 N/5]` 표시. 4턴째부터 ⚠️ 경고, 5턴째 🛑 상한 도달.

### 일반적인 턴 소비 예상 (번들링 적용)

A-0이 Go로 끝나는 건강한 흐름:

| 턴 | 플래너 메시지 | Claude 응답 |
| --- | --- | --- |
| 1 | 러프 덤프 + `A-0 시작` | 메인 라인 3~5줄 추출 후 확인 요청 |
| 2 | 메인 라인 확인·수정 지시 | **번들**: 핵심 가설 + MVP 3개 옵션·추천 + 왜 지금인가 복수 초안 + 누가 쓰는가 초안 |
| 3 | 번들 전체에 한 번에 답변 (선택·수정) | 전체 조립 초안 + Kill 이유 3개 + 판정 추천 |
| 4 | 최종 리뷰·수정 지시 | 클린 최종본 |
| 5 | Go 판정 | 종료 + A-1 진입 안내 |

이보다 많이 쓰면 뭔가 막힌 것이다. 5턴 초과 시 Claude가 Kill 이유 3개 제시, 10턴 초과 시 강한 Kill 권고.

## STEP 0에서 STEP 4까지 Claude가 지키는 원칙 요약

정책 v11의 5가지 공통 작성 원칙과 6가지 AI 역할을 A-0에 적용하면:

**작성 중:**
- 메인 라인 먼저 (원칙 1) — STEP 1이 이걸 강제함
- 예시 없는 추상 정의 금지 (원칙 3) — 핵심 가설·유즈케이스에 반드시 구체 예시
- 메타 정보 금지 (원칙 4) — 작성일·상태·전제 블록 쓰지 않음
- 플래너 판단은 선택형 Q&A + 초안 떠넘기기 금지 (원칙 5) — STEP 2에서 Claude가 복수 초안 + 추천 + 이유를 먼저 낸다
- 번들링 (역할 5) — STEP 2에서 핵심 가설 + MVP 3개 + 왜 지금 + 누가 쓰는가를 한 응답에 묶는다

**전달 직전:**
- 안 읽힘 탐지기 9항목 스스로 돌린다 (역할 3)
- "Kill할 이유 3개" 필수 첨부 (역할 1)

**수정 시:**
- 지적받은 곳만 수정 (역할 4)
- 변경 가시화 (역할 6) — 수정된 섹션에 🔄 마크

## A-0에서 흔한 실패 모드

**실패 1: 핵심 가설이 너무 넓음**
- 예: "사람들이 AI로 고민을 해결하고 싶어한다"
- 왜 나쁜가: 누구인지·언제인지·뭘 하는지 없음 → 검증 불가능
- 교정: "[누가] [언제] [뭘]"이 다 들어가야 함

**실패 2: MVP 경계가 복수**
- 예: 제품란에 "사주 해석 + 타로 + MBTI"
- 왜 나쁜가: 검증 축이 흐려짐. 하나 실패해도 원인 식별 불가
- 교정: 하나만 남기고 나머지는 "배제한 것"으로

**실패 3: 왜 지금인가가 비어있거나 일반론**
- 예: "AI 시대가 왔기 때문에"
- 왜 나쁜가: 모든 아이디어에 해당 → 이 아이디어만의 타이밍 설명 아님
- 교정: "지난 X달 사이에 Y가 바뀌어서 Z가 가능해졌다"

**실패 4: 유즈케이스가 Phase·Step으로 체계화됨**
- 왜 나쁜가: A-0은 메인 라인만. 체계화는 A-1의 일
- 교정: 3~5줄로 다시 요약

**실패 5: Kill 이유 3개를 Claude가 약하게 씀**
- 예: "경쟁사가 있을 수 있다", "반응이 예상보다 낮을 수 있다"
- 왜 나쁜가: 완충어 남발 + 구체성 없음
- 교정: 구체적이고 강한 kill 시나리오 3개. 완충어 금지.

**실패 6: Claude가 초안을 플래너에게 떠넘김 (사주톡 테스트에서 발견)**
- 예: "Eugene이 생각하신 거 있으시면 한 줄 주세요 / 없으시면 '초안 줘' 해주세요"
- 왜 나쁜가: 플래너 판단 지점에 Claude가 판단 회피. 정책 v11 원칙 5 위반
- 교정: Claude가 먼저 복수 초안 2~3개 + 추천 + 이유. 플래너는 고르거나 수정

## A-1 진입 조건 (Go 판정 시)

A-0가 Go로 끝나면 **A-1 (유즈케이스 분해)**로 진입한다. A-1에 넘길 것:

- 확정된 핵심 가설 한 문장
- 확정된 러프 유즈케이스 메인 라인
- 확정된 MVP 경계 3개 (제품·타겟·목표 행동)

A-1는 이 메인 라인을 Phase·Step 체계로 분해해서 **개발 가능한 프로세스**로 만드는 작업이다. 채널·실행안 유형은 A-1 또는 A-2에서 결정한다.

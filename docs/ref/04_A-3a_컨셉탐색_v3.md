> 00 기획 하네스 정책 v15을 토대로 한다. 작성 전 정책 문서의 "안 읽힘 6원인"·"문장 원칙"·"AI의 역할"·"번들링"·"변경 가시화"·"턴 카운팅"을 참조한다.

## 이 문서 사용법

A-3a는 **하네스의 네 번째 핵심 문서**이다. A-2에서 확정된 와이어프레임에 **시각 디자인 컨셉**을 입힌다. 정확히는 **메인 화면 1~2개에 대해 디자인 변형 3~5개를 만들고 그 중 하나를 컨펌**하는 단계.

A-3a 끝나면 A-3b(전체 화면 적용)로 진입.

**v1의 핵심 디자인 결정 — 사람 디자이너 best case 따름:**

```
A-3a (이 문서)
  메인 화면 1~2개 + 톤·팔레트·폰트·참조 DESIGN.md 결정
  → a-3a.md 출력 (디자인 도구 입력)
  
[디자인 도구 작업 — Eugene 직접]
  Stitch / Claude Design에서 변형 3~5개 생성, 컨펌
  → DESIGN.md export

A-3b (별도 문서)
  DESIGN.md 적용해 나머지 모든 화면 자동 생성
  → handoff bundle 출력 (B-1 입력)
```

**왜 분할하는가:**

사람 디자이너 best case 워크플로우. 사람 디자이너는 (1) 메인 화면 1~2개에 대해 3~5개 컨셉 → (2) 컨펌 → (3) 컨펌된 컨셉으로 나머지 모든 화면 디자인. 한 번에 모든 화면 디자인하지 않는다. AI도 분할이 더 좋은 결과.

**Google DESIGN.md 표준 채택:**

Google Stitch가 2026.4.21 오픈소스화한 DESIGN.md 형식을 산출물 표준으로 채택. 우리만의 형식 안 만든다. 이유: README.md가 코드 컨벤션 표준이듯 DESIGN.md가 디자인 시스템 표준이 되는 중. Claude Code·Cursor·Stitch·Claude Design 모두 자동 인식. 423개+ 무료 참조 라이브러리.

**참조 라이브러리 통합:**

A-3a에서 0에서 디자인 시작 안 함. designmd.app·awesome-design-md에서 검증된 베이스 시스템 추천 → 도메인에 맞게 수정.

## 도구 선택 — Stitch (디폴트) vs Claude Design vs v0

| 상황 | 추천 도구 | 이유 |
|---|---|---|
| 신규 프로젝트, 코드 없음 | **Stitch** (디폴트) | 무료, DESIGN.md 자동 export, 무한 캔버스 |
| 기존 코드 있음 | **Claude Design** | 코드베이스 ingest, handoff bundle 직접 |
| 빠른 프로덕션 | **v0** | shadcn/ui 기반 production-ready 코드 |

**디폴트는 Stitch.** Google Labs 베타 무료. 월 350회 표준 + 200회 프로 생성 한도. DESIGN.md 자동 export.

**사주톡 같은 케이스(이미 코드 있음)는 Claude Design.** 코드베이스 ingest로 기존 구조 보존. handoff bundle 직접 생성.

### 산출물 구조 (a-3a.md)

```
[맨 앞] 1차 독자 선언문 (1차: 디자인 도구 AI, 2차: Eugene)

   3-a. 톤 (3개 옵션 + 추천)

   3-c. 폰트 페어링 (영문+한글)
   3-d. 보이스·텍스트 톤
4. 참조 DESIGN.md 후보
   4-a. designmd.app·awesome-design-md에서 톤 매칭 후보 3개

   5-c. v0 프롬프트 초안 (대안)
6. [SO 결정 필요]
7. Kill / Go / Hold

[맨 끝] Claude의 적대적 압박 — Kill 이유 3개
```

### DESIGN.md 산출물 형식 (Google 표준)

DESIGN.md = **YAML 프론트매터(머신 읽기) + Markdown 본문(사람 읽기)**.

**예시 (사주톡):**

```yaml
---
name: 사주톡
colors:
  primary: "#2D1B3D"
  secondary: "#1A1428"
  accent: "#C9A961"
  textPrimary: "#F5F0E8"
  textSecondary: "#8C7A4F"
  error: "#B85450"
typography:
  h1:
    fontFamily: Cormorant Garamond
    fontSize: 2.5rem
    fontWeight: 500
  body:
    fontFamily: Pretendard
    fontSize: 1rem
spacing:
  sm: 8px
  md: 16px
  lg: 24px
rounded:
  sm: 4px
  md: 8px
---

## Overview
신비로운 + 따뜻한. 어두운 보라 베이스에 골드 액센트.
역술가 대면 분위기를 시각으로 구현.

## Colors
- **Primary (#2D1B3D):** 화면 배경, 헤더. 어두운 보라가 "긴 해석을 차분히 읽는" 분위기 유도.
- **Accent (#C9A961):** 카운터·버튼·강조. 골드는 시각 무게가 있어 사용자 자연스럽게 의식 — UX 의도 직결.
- **Text Primary (#F5F0E8):** 본문. 따뜻한 화이트로 어두운 배경 가독성 우선.

## Typography
영문 세리프(격조) + 한글 산세리프(가독성) 페어링.

## Voice
부드러운 존중. 존댓말. 명령 금지. "입력하세요" → "알려주실래요?".
역술가 톤이지만 위압 없음.
```

**파일 위치:** repo 루트에 `DESIGN.md`. Claude Code·Cursor·Stitch가 자동 인식.

## 섹션별 상세

### 1. A 트랙 요약 블록

A-0·A-2 핵심을 맨 앞에 고정.
- A-0 핵심 가설 한 문장
- A-0 타겟
- A-2 화면 목록 (이름·번호만)
- MVP 경계 3개

### 2. 메인 화면 선정

**왜 별도 섹션인가:** 사람 best case는 메인 화면 1~2개에 대해 변형. 모든 화면 아니다.

**선정 기준:**
- 핵심 가설 검증에 직접 관련된 화면
- 사용자가 가장 오래 머무는 화면
- 첫인상 결정 화면

**좋은 예시 (사주톡):**
```
메인 화면 후보:
- 화면 1 (랜딩) — 첫인상
- 화면 4 (긴 해석) — 사용자 가장 오래 머무는 곳, 핵심 가설 검증 직결
- 화면 5 (질문 프롬프트) — Q&A 루프 진입점

Claude 추천: 화면 4 + 화면 5 (대화 흐름 페어)
이유:
1. 핵심 가설("3번 질문 다 씀")이 화면 4·5 흐름에서 검증
2. 두 화면 시각적 연결 검증 가능
3. 화면 1은 화면 4 디자인 시스템 따라 도출 가능
```

**선정 개수: 1~2개.** 3개+ 변형 비교 부담 큼.

### 3. 디자인 방향 결정

**3-a. 톤** — 옵션 3개 + 추천 + 이유.

**좋은 예시 (사주톡):**
```
톤 옵션:
- 옵션 A: 신비로운 + 따뜻한 (어두운 보라 + 골드)
  + 사주의 "운명·해석" 분위기 정합
  + 몰입감 — 긴 해석을 진지하게 읽도록
- 옵션 B: 모던·실용 (밝은 베이지 + 짙은 네이비)
  + 거부감 적음
  - 사주의 신비감 약화
- 옵션 C: 따뜻한 미니멀 (연한 핑크 + 따뜻한 회색)
  + 28~34세 여성 타겟 친숙
  - 사주 도메인 무게감 부족

Claude 추천: A
이유: 핵심 가설 "긴 해석을 끝까지 읽고 3번 질문"이 몰입 환경에서 더 자주 발생.
```

**3-b. 컬러 팔레트 시드** — HEX 4~6색. "시드"는 디자인 도구가 변형 미세조정.

**3-c. 폰트 페어링** — Google Fonts 우선. 한글 폰트 필수.

**3-d. 보이스·텍스트 톤** — UI 텍스트 어조. 시각만큼 중요.

### 4. 참조 DESIGN.md 후보 (v1 핵심 신규)

**A-3a 가장 큰 차별화 — 0에서 시작 안 함.**

Claude가 designmd.app·awesome-design-md·designmd.ai에서 톤 매칭 후보 검색.

**좋은 예시 (사주톡):**
```
참조 DESIGN.md 후보:

후보 1: Linear (https://designmd.app/linear)
- 톤: 어두운 모던 (사주톡 톤 A 매칭 60%)
- 강점: 어두운 톤 + 강렬한 액센트 균형
- 약점: 골드 색상 없음. 보라 약함.

후보 2: Vercel (awesome-design-md/vercel)
- 톤: 미니멀 다크
- 강점: 가독성 우수
- 약점: 따뜻함 부족, 사주 감성과 거리

후보 3: 직접 검색 키워드: "purple gold luxury dark"
designmd.app 검색 → Eugene 마음에 드는 것 베이스로

Claude 추천: 후보 1 (Linear) 베이스 + 컬러만 변경
이유:
1. 어두운 모던 구조 보존 (가독성 검증됨)
2. 컬러만 보라+골드로 교체하면 사주톡 톤 완성
3. 0에서 시작 아니라 70% 완성된 시스템에서 시작
```

**왜 도움 되는가:**
- LLM은 매 프롬프트 독립 처리. 참조 없으면 매번 다른 결정
- 검증된 시스템에서 시작 → 일관성·접근성 자동
- Eugene이 0에서 평가 안 하고 70% 완성에서 미세조정

**참조 라이브러리 목록:**
- **designmd.app** — 423개 AI-ready 디자인 시스템
- **VoltAgent/awesome-design-md** — Stripe·Vercel·Linear·Notion 등 69개+
- **designmd.ai** — 100개+ 무료
- **getdesign.md** — 인기 웹사이트 영감 컬렉션

## A-3a 흔한 실패 모드

**실패 1: 메인 화면 너무 많이 선정**
- 예: 화면 8개 모두
- 왜 나쁜가: 변형 비교 부담 폭증, 디자인 도구가 일관성 못 잡음
- 교정: 1~2개. 핵심 가설 직결.

**실패 2: 톤이 추상**
- 예: "모던하고 깔끔하게"
- 왜 나쁜가: 도구가 매번 다르게 해석
- 교정: 옵션 3개 + HEX 코드

**실패 3: 컬러가 색 이름만**
- 예: "보라색 + 금색"
- 왜 나쁜가: 어떤 보라·어떤 금인지 모름
- 교정: HEX + 역할 명시 (Primary·Accent)

**실패 4: 한국어 폰트 누락**
- 예: 영문 폰트만
- 왜 나쁜가: 한글 사용자 타겟인데 한글 폰트 미정
- 교정: 영문·한글 둘 다. Google Fonts 우선.

**실패 5: 참조 DESIGN.md 안 활용**
- 예: 0에서 시작
- 왜 나쁜가: 검증 안 된 디자인. 일관성·접근성 직접 검증해야 함
- 교정: designmd.app·awesome-design-md에서 베이스 → 도메인 수정

**실패 6: A-2 UX 의도와 단절**
- 예: "카운터 우측 상단 골드"라고만 적고 A-2 UX 의도와 연결 안 함
- 왜 나쁜가: 디자인이 UX 의도 안 살림 → 핵심 가설 검증 약화
- 교정: 각 디자인 결정 옆에 "A-2 §4 UX 의도와 연결" 명시

**실패 7: DESIGN.md를 비표준 형식으로 작성**
- 예: YAML 프론트매터 없이 마크다운 본문만
- 왜 나쁜가: Claude Code·Cursor·Stitch가 머신 토큰 못 읽음
- 교정: Google 공식 스펙 준수. 검증 도구: `npx @google/design.md lint`

**실패 8: A-3a에서 모든 화면 디자인하려 함**
- 예: 메인 1~2개 아니라 모두
- 왜 나쁜가: 컨셉 탐색 단계 부담 폭증, 사람 best case 위배
- 교정: A-3a는 메인만, A-3b에서 나머지 자동 적용

**실패 9: 보이스·텍스트 톤 누락**
- 예: 시각만 결정하고 UI 텍스트 톤 안 박음
- 왜 나쁜가: 빌드 도구가 디폴트 텍스트 사용 → 톤 깨짐
- 교정: §3-d에 보이스 규칙 + 예시 텍스트. DESIGN.md `## Voice` 섹션에 명시.
